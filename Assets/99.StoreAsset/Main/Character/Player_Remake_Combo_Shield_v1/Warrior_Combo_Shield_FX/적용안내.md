# 솔져 리메이크 · 워리어 추가 공격 · 방패

프로젝트 밖에서 제작한 개별 투명 PNG입니다. 프로젝트 파일, 애니메이션, 프리팹, 코드는 수정하지 않았습니다. 현재 SpriteLibrary에 연결된 원본 파일과 메타 설정을 조사해 캔버스와 피벗을 맞췄습니다. Unity에서의 최종 재생·판정 검증은 아직 하지 않았습니다.

## 구성

| 구분 | 제공 내용 |
|---|---|
| 솔져 | Bullet / Lazer / Missile / Grenade / Sniper 각각 Idle 4컷 + Attack 4컷, 총 40컷 |
| 솔져 해상도 | 같은 40컷을 64×64 교체용과 1024×1024 고해상도용으로 제공 |
| 자이언트소드 | Attack2 4컷, Attack3 4컷 |
| 해머 | Attack2 4컷, Attack3 4컷 |
| 무기 궤적 | 두 무기 × 1·2·3단 × 4컷 = 24컷, 캐릭터와 분리 |
| 방패 | Idle 4컷, Attack 4컷, Guard 참고용 1컷 |
| 방패 이펙트 | 전방 하늘색 충격파 8컷 |
| 참고 | 기존 워리어 1단 공격 8컷 복사본, 미리보기 GIF/JPG |

솔져는 하나의 새 본체를 모든 무기에 공통으로 사용했습니다. 총기 공격은 반동, 수류탄은 팔의 준비·투척·회수로 표현했습니다. Idle은 흉부 명암의 작은 변화입니다. 워리어는 기존 Attack 2번 컷의 본체 픽셀과 실제로 들고 있던 무기를 분리·재조합했습니다. 추가 공격은 고정된 본체 자세를 중심으로 무기를 회전시킨 방식이며, 전신을 새로 그린 16개 포즈는 아닙니다. 신규 방패와 솔져 원화는 이미지 생성 도구로 제작하고, 크기·배치는 픽셀 합성으로 정렬했습니다. 사용 프롬프트는 Generation_Prompts.json에 있습니다.

## 크기와 Import 설정

| 파일 | 이미지 크기 | Pixels Per Unit | Pivot |
|---|---|---|---|
| Soldier/DropIn_64 | 64×64 | 100 | Center (0.5, 0.5) |
| Soldier/HD_1024 | 1024×1024 | **1600** | Center (0.5, 0.5) |
| Warrior 아래 완성 캐릭터·이펙트 | 3072×3072 | 100 | Custom **(0.5, 0.423828125)** |

- Texture Type: Sprite (2D and UI), Sprite Mode: Single, Alpha Is Transparency 활성화.
- 픽셀 표현은 Filter Mode: Point, Compression: None을 기준으로 제작했습니다.
- Transform Scale은 기존 값을 유지하세요. 솔져 HD를 PPU 100으로 가져오면 16배 커집니다.
- 원본 해상도를 유지하려면 Max Size가 솔져 HD는 1024 이상, 워리어는 4096 이상이어야 합니다. 기존 워리어의 플랫폼별 압축/축소 설정도 함께 확인하세요. 기존과 새 파일의 실제 Import 조건을 같게 해야 비교가 정확합니다.
- PNG의 투명 여백은 의도된 정렬 공간입니다. 자동 Trim이나 프레임마다 다른 크기의 크롭을 하면 위치가 달라집니다.
- Parts는 제작용 분리 부품입니다. 위 표의 완성 캐릭터 설정을 부품에 그대로 적용하는 용도가 아닙니다.

솔져 본체 높이는 64 버전에서 36픽셀, HD에서 576픽셀입니다. 머리 상단과 발 하단은 64 기준 y=14, y=50(끝 제외)로 맞췄습니다. 수평 위치는 원본의 발 중심을 기준으로 배치했습니다. 새 외형이므로 원본과 전체 윤곽·체형까지 같은 것은 아닙니다. 워리어의 본체는 추가 공격 사이에 확대·축소하지 않았고, 무기와 방패의 범위만 바뀝니다.

## 솔져 교체 순서

1. 선명도보다 기존 PNG와 같은 규격의 교체를 우선하면 DropIn_64를 사용하세요. HD는 PPU 1600 설정 후 별도 Sprite로 연결합니다.
2. Original_Replacement_Map.csv에서 기존 파일 경로와 새 파일을 확인하세요. 기존 PNG를 덮어쓸 때는 기존 이름과 .meta 파일을 유지해야 참조가 유지됩니다. 먼저 원본을 백업하세요.
3. 현재 솔져는 Idle과 Attack이 각각 3컷입니다. 01~03을 기존 순서에 대응시키고, 04는 SpriteLibrary 라벨과 애니메이션 키를 추가해야 사용됩니다. PNG 교체만으로 4컷 애니메이션이 되지는 않습니다.
4. 현재 Bullet과 Lazer는 Soldier.spriteLib 및 원본 그림을 공유합니다. 둘을 서로 다른 새 외형으로 쓰려면 Lazer 전용 라이브러리와 무기별 연결이 필요합니다. 같은 원본 PNG에 두 디자인을 동시에 덮어쓸 수 없습니다.
5. 기존 발사 위치와 새 총구 위치를 Scene에서 확인하세요. 캐릭터의 캔버스·피벗 일치는 총구의 세부 위치까지 일치한다는 뜻은 아닙니다. Grenade Attack 03은 수류탄이 손에서 떠난 컷이며, 발사체는 기존 게임 오브젝트로 표현합니다.

64 버전은 원본과 같은 낮은 해상도로 줄였기 때문에 작은 장식이 많이 생략됩니다. Previews/Soldier_Size_Comparison.jpg에 같은 화면 크기로 원본·64 버전·HD 버전을 비교했습니다.

## 자이언트소드·해머 추가 공격

- Attack2: 아래쪽 준비 → 정면 통과 → 위로 베기 → 회수.
- Attack3: 위로 준비 → 하강 → 아래로 내리찍기 → 다음 동작 준비.
- Attack1_Existing는 현재 사용하던 1단 공격의 비교용 복사본입니다.
- 각 Attack 폴더의 01~04를 시간순으로 배치하세요. 처음에는 12 FPS를 미리보기 기준으로 사용한 뒤 실제 공격 속도에 맞춰 조절할 수 있습니다.
- 현재 SpriteMeleeAttack은 4컷짜리 한 공격을 처리합니다. Z 유지로 1→2→3단이 나가는 기능은 이 PNG만 교체해서 생기지 않습니다. 단계별 클립·판정 프레임·입력 유지 처리의 구현은 별도 작업입니다.
- 새 무기 각도에 맞는 Custom Physics Shape도 별도로 작성해야 합니다. 자동 생성으로 캐릭터 전체 외곽을 공격 판정으로 사용하지 마세요. 기존 각도의 Physics Shape를 복사하는 것만으로는 새 궤적과 맞지 않습니다.

## 지나간 자리에 남는 궤적

Trails_Attack1~3은 각각 해당 단계의 캐릭터 프레임과 동일한 캔버스·피벗입니다. 캐릭터 Sprite에 합치지 않고 별도 SpriteRenderer에 사용하세요. 01과 04는 의도적으로 완전 투명한 꺼짐 프레임이며, 02와 03에 궤적이 있습니다.

캐릭터를 따라다니는 효과는 같은 위치에서 재생하면 되지만, 요청한 '지나간 자리에 남는 잔상'은 생성 순간의 위치·회전·좌우 방향을 저장해 월드에 남기고 짧게 소멸시키는 처리가 필요합니다. 투명 PNG 자체가 월드 위치를 고정하지는 않습니다. 기존 1단 궤적은 원본 무기로 만든 각도 근사이므로 실제 1단 애니메이션에 겹쳐 확인하고 재생 시점을 조절하세요.

## 방패: 현재 Shield 코드와 맞추기

| Attack 컷 | 용도 |
|---|---|
| 01 | 방패 올리기 시작 |
| 02 | 중간 확대 |
| **03** | **최대 확대, 키를 누르는 동안 유지** |
| 04 | 키를 뗀 뒤 회수 |

현재 Shield.cs는 Attack 클립의 50% 위치(3번 컷)를 유지하며, 화면에 표시된 Sprite가 _guardSprite와 같은 객체인지 확인합니다.

1. 라이브러리의 Attack 03과 Shield의 Guard Sprite 슬롯에는 **동일한 Warrior_Shield_Attack_03 Sprite 에셋**을 연결하세요.
2. Warrior_Shield_Guard.png는 같은 그림의 참고 복사본입니다. Attack 03은 원본 파일을, Guard Sprite는 이 복사본을 연결하면 서로 다른 Sprite 객체라 방어 판정이 비활성화됩니다. 그림이 같다고 같은 객체인 것은 아닙니다.
3. Attack 03의 Sprite Editor > Custom Physics Shape에서 **방패만 감싸는 폴리곤 하나**를 작성하세요. 현재 코드는 Physics Shape가 정확히 1개인지 검사합니다. 몸통이나 하늘색 효과까지 포함하지 마세요.
4. Impact_8frames는 별도 이펙트에 01~08 순서로 연결하세요. 오른쪽을 바라보는 기준이며 왼쪽을 볼 때 함께 반전해야 합니다. 마지막 컷은 완전 투명입니다. 24 FPS라면 약 0.33초입니다.
5. 새 전방 효과를 방패 확대 시점에 재생하는 연결은 별도로 필요합니다. 기존 _hitEffectPrefab은 피격 시 재생되는 효과이므로, 확대 순간의 효과와 발동 시점이 다릅니다.

## 검사 범위

Validation_Report.json에는 프레임 수, 실제 크기, RGBA, 가장자리 투명도, 솔져의 머리·발 높이와 파일 해시를 기록했습니다. Import_Mapping.csv에는 완성 캐릭터·이펙트별 PPU와 Pivot이 있습니다. 검사 통과는 이미지 파일 수준이며, 실제 Unity의 라이브러리 연결·애니메이션 재생·물리 판정이 검증되었다는 뜻은 아닙니다.
