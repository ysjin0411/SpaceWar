# 이동 모션 + 솔져 무기 이펙트 리메이크

2026-09-25 / 프로젝트 밖 제작본. Unity 프로젝트의 스크립트·프리팹·클립은 수정하지 않았습니다.

## 구성

- 이동: 솔져 5종 + 워리어 4종, 각 12프레임 = 108 PNG.
- 무기: 32개 세트, 270 PNG. 합계 378개 개별 투명 PNG.
- `Preview.html`: 움직이는 GIF 미리보기와 세트별 임포트 값.
- `Move_ImportSettings.csv`, `Soldier_WeaponFX/ImportSettings.csv`: 정확한 PPU, Pivot, FPS.
- `QA_Report.json`: RGBA/투명 여백/캔버스/접지 높이 검사 결과.
- 최종 완전 투명 프레임은 명중·폭발·연기 등의 소멸용입니다. 누락 이미지가 아닙니다.

## 먼저 지킬 임포트 설정

개별 PNG이므로 Texture Type = Sprite (2D and UI), Sprite Mode = Single.
Mesh Type = Full Rect, Filter Mode = Point, Compression = None, Generate Mip Maps = Off,
Alpha Is Transparency = On, Wrap Mode = Clamp. Trim/자동 여백 제거를 하지 마세요.
Max Size는 이미지 원본보다 작게 설정하지 않습니다: 3072 이미지는 4096,
1536 이미지는 2048, 솔져 이동은 1024, 이펙트는 512 이상.
캐릭터용 기존 Transform Scale을 유지하고, 반드시 아래 PPU와 Pivot을 함께 적용합니다.
PNG 자체에는 Unity의 PPU/Pivot 정보가 들어가지 않으므로 PNG 교체만으로 임포트 설정이 자동 이전되지는 않습니다.

## 이동 애니메이션

|---|---|---|---|---|
| Soldier/Bullet, Lazer, Missile, Grenade, Sniper/Move | 1024×1024 | 1600 | 0.5, 0.5 | 18 |
| Warrior/GiantSword, GiantHammer/Move | 3072×3072 | 100 | 0.5, 0.423828125 | 14 |
| Warrior/Shield/Move | 3072×3072 | 100 | 0.5, 0.423828125 | 16 |
| Warrior/Slash/Move | 1536×1536 | 100 | 0.5, 0.462239583333 | 16 |

프레임 01~12를 순서대로 사용하고 Loop Time을 켭니다. 12 Samples 기준이 아니라 **12장**입니다.
권장 Samples는 이동 속도와 보폭을 보고 최종 조절합니다. SpriteResolver를 계속 쓴다면
기존 방식대로 무기별 Move 카테고리에 01~12 라벨을 등록해 클립에서 교체합니다.
이동은 제자리 보행입니다. 이미지 안에서 캐릭터 전체가 앞으로 이동하지 않습니다.
원본 픽셀의 몸통·무기를 유지하고 다리를 관절별로 합성했습니다. 머리/몸통/무기를 프레임별로 확대하지 않았습니다.
Shield는 같은 워리어의 가리지 않은 다리 원본을 합성했습니다.
모든 이동 프레임의 접지선은 원본과 같습니다: 솔져 y=800, 일반 워리어/Shield y=2000, Slash y=1056 (이미지 위쪽 원점).
무기 높이가 서로 달라도 전체 이미지를 같은 높이로 자동 맞추면 안 됩니다. 캐릭터 몸체의 배율이 달라집니다.
외형과 설정은 파일 수준에서 확인했습니다. 실제 이동 속도에 대한 발 미끄러짐은 인게임에서 확인해야 합니다.

### 발사체 크기

기존 저장 파일의 알파 영역과 프리팹 스케일을 확인하여, 최대 길이/높이 기준을 맞췄습니다.
새 디자인의 가로세로 비율은 기존 도형과 다르므로 윤곽이나 두께까지 동일한 것은 아닙니다.

| 무기 | 새 PPU | 현재 Root Scale | 기존 알파 크기 기준 | 새 기준 크기 |
|---|---|---|---|---|
| Bullet | 2000 | 2.5 | 9px / PPU100 ×2.5 | 길이 0.225 world |
| Sniper | 800 | 1 | 46px / PPU100 | 길이 0.46 world |
| Grenade | 800 | 1 | 22px / PPU100 | 세운 상태 높이 0.22 world |
| Missile | 800 | 2 | 44px / PPU100 ×2 | 길이 0.88 world |
| Lazer | 800 | 새 탄환 Root 1 권장 | 기존은 지속 LineRenderer | 새 에너지탄 길이 0.36 world |

Bullet/Sniper/Missile/Lazer는 오른쪽(+X)이 진행 방향이며 Pivot Center입니다.
총구 효과 Muzzle/Launch는 Pivot **(0.125, 0.5)**를 총구 끝에 둡니다.
Missile/Exhaust는 Pivot **(0.9, 0.5)**를 노즐에 두며 불꽃은 왼쪽(-X)으로 나갑니다.
현재 Missile Root Scale 2를 그대로 상속하는 기준입니다.
Grenade/Tumble은 회전이 이미지에 들어 있습니다. 같은 렌더러를 코드에서도 회전시키면 이중 회전합니다.
Armed는 별도 선택 사항으로, 지면에서 기폭 직전 표시를 쓸 때 사용합니다.

### Sniper 관통/잔상

Projectile은 탄환 본체, Trail은 지나간 자리에 남는 별도 이미지입니다.
Trail은 01~12를 30fps, Loop Off로 재생합니다. 현재 _trailSpacing 0.4와 비교해 겹치도록 약 0.56 world의 밝은 선을 뒀습니다.
PenetrationHit은 적의 충돌 위치에 독립적으로 재생합니다. 이 효과가 끝날 때 탄환을 없애는 뜻이 아닙니다.
피해 적용·관통 횟수는 코드 기능이므로 스프라이트로 바뀌지 않습니다.

### Lazer는 연사 에너지탄

이 패키지는 지속 광선이 아닌 **독립된 짧은 에너지탄을 연속 발사**하는 용도입니다.
Projectile 8장은 비행 중 루프, Muzzle은 한 번 발사할 때 한 번,
Hit은 명중 위치에서 한 번 사용합니다. 기존 Lazer.cs는 LineRenderer 방식이므로
이 이미지를 넣는 것만으로 연사 무기가 되지 않습니다. 발사 주기/이동/충돌/피해 처리 전환은 이후 별도로 진행합니다.
이전의 청색→적색 변화는 연사탄에도 사용할 수 있도록 준비했습니다.
기본 Projectile/Muzzle/Hit은 청색, 이름 끝 Warm은 주황색, Hot은 적색입니다.
세 단계의 캔버스·피벗·실루엣이 같으므로 단계 교체로 크기가 변하지 않습니다.
꾹 누르는 시간에 따른 과열과 적색 최대 피해는 이미지가 아닌 코드에서 적용해야 합니다.

### 수류탄/미사일 폭발: 두 방식 중 하나

1. **현재 SpriteExplosionEffect 코드를 유지할 경우**:
   StaticCore_ForCurrentTween 한 장을 Core Renderer에,
   StaticShockwave_ForCurrentTween 한 장을 Shockwave Renderer에 사용합니다.
   현재 코드가 확대·페이드를 담당합니다. 이 두 파일은 기존 방식 호환용입니다.
2. **새 프레임 애니메이션을 사용할 경우**:
   ExplosionCore 20장 24fps(약 0.833초), Shockwave 16장 24fps(약 0.667초), Loop Off.
   이미지 자체에 확산이 들어 있어 해당 렌더러의 추가 DOScale 확대와 겹치지 않도록 해야 합니다.
   Core와 Shockwave는 동시에 시작하며 필요하면 Smoke를 18fps로 추가합니다.
   새로운 프레임 재생/정리 연결은 별도 적용 작업입니다.

Grenade 폭발 PPU112, Missile 폭발 PPU149.333333, Pivot Center, 폭발 Root Scale1 기준입니다.
충격파의 최대 반지름은 224px이므로 각각 지름4/지름3 world(현재 피해 반경2/1.5)에 대응합니다.
소멸 마지막에 최대 크기와 알파0에 도달합니다. 충격파는 연출이며 Collider 변경은 하지 않습니다.
기존 코드용 단일 충격파는 최대 지름의 정적 이미지입니다.
폭발 중심의 불꽃·연기는 충격파 안쪽에 있으며 필수적으로 판정 전체를 불투명하게 채우지 않습니다.

## 제작/검사 범위

새 발사체·폭발·전기 명중 원화는 내장 이미지 생성 도구로 제작했습니다.
사용자가 동의한 원본 픽셀 합성·정렬 방식으로 이동 모션, 발광 변화, 잔상, 분리·정렬·소멸 프레임을 제작했습니다.
겹치던 초기 폭발 시트는 폐기하고 간격을 넓힌 새 시트에서 분리했습니다.
모든 최종 PNG의 알파 채널, 이미지 경계 잘림, 세트별 캔버스 크기와 이동 접지선을 검사했습니다.
미리보기의 어두운 배경은 GIF/JPG 확인용이며 실제 PNG에는 들어 있지 않습니다.
Unity 플레이모드 검증/실제 프리팹 연결은 아직 수행하지 않았습니다.
