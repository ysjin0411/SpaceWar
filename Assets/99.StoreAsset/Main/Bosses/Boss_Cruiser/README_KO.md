# Boss_Cruiser 적용 가이드

## 구성
본체 9장: Base 1장, Idle 4장, Attack 4장. 모두 256×128px.
타워 A/B/C 각각 5장: Base 1장, Attack 4장. 모두 64×80px.
게임용 PNG 총24장, 투명 RGBA. A 쌍열포 / B 플라즈마포 / C 미사일 포드.
본체에는 장착구만 그려져 있고 타워는 독립 오브젝트로 배치합니다.
본체와 모든 타워는 왼쪽을 향합니다.

## Unity 임포트
Sprite (2D and UI), Single, PPU 100, Point (no filter), Compression None.
Alpha Is Transparency 켜기.
본체 Pivot: Center (0.5, 0.5).
타워 15장 Pivot: Custom (0.5, 0.05).
타워 바닥 기준은 좌상단 기준 (32,76)px, 즉 하단에서 4px입니다.
자동 트리밍을 하지 마세요. 고정 캔버스와 Pivot을 유지해야 프레임 위치가 맞습니다.
크기 변경은 본체와 타워를 포함한 공통 부모의 Scale로 조절하세요.

## 조립 좌표
본체와 타워가 같은 부모의 자식이며 각 자식 Scale=(1,1,1), PPU=100일 때:
| 타워 | Local Position | 본체 좌상단 기준 부착점(px) |
|---|---|---|
| A | (-0.16, 0.17, 0) | (112,47) |
| B | (0.21, 0.15, 0) | (149,49) |
| C | (0.55, 0.12, 0) | (183,52) |

타워 Sorting Order=10, 본체=11처럼 본체가 타워 앞에 그려지게 하세요.
받침대와 수납된 포탑은 함체 뒤에 가려지고, 상승한 포탑만 위로 드러납니다.
Base에서는 장착구만 보입니다. 프레임마다 타워 Transform을 이동하거나 Scale을 변경하지 마세요.
장착구 중심 X는 112 / 149 / 183px입니다.

## 애니메이션
본체 Idle: Idle_01 → 02 → 03 → 04 → 반복.
본체 Attack: Attack_01(전개) → 02(완전 전개/충전) → 03(발사) → 04(복귀 중) → Idle.
타워: Base → Attack_01(상승) → 02(완전 전개) → 03(발사) → 04(하강) → Base.
발사 타이밍은 모두 Attack_03입니다. 프레임 시간은 0.12~0.18초부터 조절하세요.
완전 전개 대기는 Attack_02를 더 길게 유지하면 됩니다.
본체 발사 포구는 Attack_03 이미지 좌상단 기준 약 (16,68)px입니다.
발광 이펙트의 끝과 실제 포구는 구분하세요.

## 다음 구현 단계
각 타워의 체력/콜라이더, 전개 프레임에 따른 BoxCollider2D Size/Offset 변경,
모든 타워 파괴 후 본체 피격 허용은 별도 게임 로직으로 연결합니다.
수납 시 충돌을 끄고, 상승 시 함체 밖으로 드러난 몸체만 충돌 범위로 삼을 수 있습니다.
PNG 프레임 교체만으로 Collider 크기가 자동 변경되지는 않습니다.

## 제작 및 검증
내장 image_gen으로 개별 생성/수정 후 최근접 샘플링으로 크기를 맞췄습니다.
타워는 고정 받침대 너비와 바닥 위치를 기준으로 정렬했습니다.
24장 모두 규격, 투명 픽셀 존재, 캔버스 가장자리 잘림 여부를 확인했습니다.
validation.txt의 edge=0은 알파16 이상 픽셀이 가장자리에 닿지 않는다는 뜻입니다.
최종 프롬프트는 Prompts.txt에 있습니다.
프로젝트 파일은 수정하지 않았으며 Unity 실제 재생 테스트는 수행하지 않았습니다.
