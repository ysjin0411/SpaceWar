# Stage 2 Final Boss — Phase 1
내장 image_gen으로 생성한 개별 PNG 20장입니다. 프로젝트 파일은 수정하지 않았습니다.
범위: 요청한 1페이즈 시각 에셋과 그랩 구현용 부품, 화면 균열, 열린 해치 1장. 2·3페이즈의 별도 캐릭터 애니메이션이나 특수 패턴 구현은 포함하지 않습니다.

## 구성
- Base.png: 기본 로봇, 닫힌 흉부 해치
- Idle_01~04.png: 대기 4프레임
- Grab_01~06.png: 준비 → 팔 발사 → 최대 신장 → 집게 닫기 6프레임
- Shield.png: 로봇 그림을 포함하지 않는 독립 보호막
- Body_Modular.png: 그랩 팔을 분리한 본체
- Hand_Open.png / Hand_Closed.png: 독립 손과 손목
- Arm_Segment.png: 독립 연장 팔
- Crack_01~03.png: 화면 왼쪽 충돌 균열 3종 (누적 합성본이 아니라 개별 표시용)
- Hatch_Open.png: 열린 해치, 조종석은 비어 있음

## 투명도와 크기 검증
모든 PNG는 1254×1254이며 실제 알파 투명 픽셀이 있습니다. 불투명 체크무늬 배경이 아닙니다.
한 PNG에 한 에셋만 배치했습니다. 픽셀 검사에서 알파 128 이상 영역은 어느 파일에서도 캔버스 테두리에 닿지 않았습니다.
validation.json에 파일별 크기, 알파 픽셀 수와 가시 영역 경계를 기록했습니다.

같은 캔버스 크기와 완전 동일한 본체 픽셀 정렬은 다릅니다.
본체 프레임의 머리 상단은 y=153~159, 발 하단은 y=1144~1148 범위입니다.
미세한 생성 차이가 있으므로 픽셀 단위로 완전히 고정된 애니메이션이라고 보장하지 않습니다.
이미지 생성만 사용했고, 별도로 문의한 Python 크기·정렬 보정은 실행하지 않았습니다.

## Unity 크기 설정
기존 크루저 Base 파일은 256×128, PPU 100입니다. 이번 원본은 고해상도이므로 그대로 PPU 100을 쓰면 크게 보입니다.
아래 값은 원본을 수정하지 않고 약 3 Unity unit 높이의 본체로 표시하기 위한 시작 설정입니다. 실제 씬에서 최종 크기를 확인하세요.

- Texture Type: Sprite (2D and UI)
- Sprite Mode: Single
- Filter Mode: Point
- Compression: None
- Generate Mip Maps: Off
- Max Size: 2048 (1254 원본이 임의로 축소되지 않게)
- 본체 Base / Idle / Grab / Body_Modular / Hatch_Open: PPU 330, Transform Scale (1,1,1)
- 같은 본체 애니메이션에는 동일한 Pivot 사용: Custom (0.662, 0.481), 대략 몸통 중심
- 분리 손 두 장: PPU 600을 시작값으로 사용. 둘 다 동일 PPU와 Pivot 사용.
- 연장 팔: PPU 600을 시작값으로 사용. 손과 연결할 때 실제 굵기 확인.
- 보호막: PPU 330, 별도 자식 Renderer. 본체에 맞춰 크기/위치 조절.
  시작값 예시: 보호막 Pivot Center, localPosition 약 (0.28, 0, 0), localScale (1.3,1.2,1).
  이 값은 원본 가시 영역을 토대로 잡은 값이며 Unity에서 검증한 값은 아닙니다.
- UI 균열: Canvas의 Image로 사용. Set Native Size 대신 RectTransform 크기로 표시 크기 지정.
  이미지 내부 충돌 중심이 왼쪽에서 약 70~100px 떨어져 있으므로 표시 위치를 그만큼 화면 밖으로 보정.
  균열 세 개는 서로 다른 높이에 배치하면 겹치지 않습니다.

## 그랩 구현에 사용할 구성
고정 길이 연출을 재생할 때는 Grab_01~06을 사용할 수 있습니다.
사용자가 지정하는 팔 길이, 추적 방향, 잡은 뒤 이동·흔들기·던지기는 분리형 부품 구성이 적합합니다.
준비 동작 후 Body_Modular + Arm_Segment + Hand_Open으로 전환하고 손목 위치를 이동합니다.
명중 시 Hand_Closed로 변경하고 손 내부 GrabPoint로 플레이어를 보간 이동합니다.
팔은 보스 쪽 연결점과 손목 연결점 사이를 잇도록 배치합니다.
전체 그랩 프레임과 분리형 팔을 동시에 표시하면 팔이 두 개 생기므로 둘 중 하나만 표시하세요.
흔들기/뒤로 당기기/던지기는 Transform 움직임으로 처리할 수 있어 별도 스프라이트가 필수는 아닙니다.

## 보호막 피격 표시
현재 프로젝트의 컴포넌트 이름은 EnemyHitFlash입니다.
같은 오브젝트에 SpriteRenderer가 필요하고, 부모에서 IDamageable을 찾으며,
Material에 _HitFlash 프로퍼티가 있어야 합니다.
방어막 이미지 파일 자체에는 피격 코드나 Material이 포함되어 있지 않습니다.
2페이즈에서 보호막 자식 오브젝트를 끄면 시각 레이어와 해당 컴포넌트가 함께 비활성화됩니다.
페이즈 전환 중 무적 처리는 스프라이트와 별개로 보스의 피해 허용 조건에서 구현해야 합니다.
