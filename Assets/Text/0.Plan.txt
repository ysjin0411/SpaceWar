에일리언 보스 2페이즈 작업 인수인계

1. 사용자 작업 원칙

나는 게임 클라이언트 개발자로 취업을 준비하고 있다.

- 프로젝트 파일은 절대 직접 수정하지 말고, 최신 파일을 읽어서 내가 직접 작업할 수 있도록 설명해줘.
- 코드를 제공할 때는 각 코드의 기능을 주석으로 설명해줘.
- 필드 설명도 Tooltip 속성 대신 일반 주석으로 작성해줘.
- nullable은 사용하지 마.
- 임시방편 대신 기존 구조에 맞는 구현을 안내해줘.
- 에셋은 기존 외형과 크기를 맞추고 투명 배경으로 제작해야 해. 이미지가 겹칠 우려가 있으면 개별 파일로 제공해줘.
- 이전 설명을 그대로 반복하기 전에 실제 최신 프로젝트 파일부터 확인해줘.

이 문서는 2026년 9월 22일, 이전 PC에 저장된 프로젝트를 기준으로 작성했다. 새 PC에서 추가 변경이 있다면 최신 파일을 우선한다.

2. 프로젝트와 현재 목표

C:\YSJ\SubPF

현재 목표는 에일리언 보스의 2페이즈 패턴 3개를 준비하는 것이다. 먼저 스프라이트와 애니메이션·표현 구조를 정리하고, 이후 기존 BossPattern 기반 전투 구조에 연결하려고 한다.

아직 2페이즈 공격이 구현됐다고 가정하면 안 된다.

3. 구현할 패턴

① 예측 도약

멀리 있는 플레이어에게 접근하는 공격이다.

플레이어 이동 관찰 → 예상 착지점 표시 → 착지점 고정 → 도약 → 착지 공격과 충격파 → 후딜레이

착지점이 고정된 이후에는 플레이어를 계속 따라가며 목표 지점을 갱신하지 않는다.

원래 기획에는 몸을 웅크리는 동작이 있었지만, 현재 최종 Idle/Leap 에셋은 아래 설명처럼 같은 윤곽을 유지하는 발광 변화 이미지다. 실제 웅크림 자세가 준비돼 있다고 설명하면 안 된다.

② 추적 후 방향 고정 연속 할퀴기

플레이어에게 접근 → 첫 번째 할퀴기 → 두 번째 할퀴기 → 전방으로 크게 내려찍기

각 타격은 다음 단계로 구성한다.

준비 중 조준 → 방향 고정 → 공격 → 회수

공격 중에는 회피한 플레이어를 따라 회전하면 안 된다. 다음 타격의 준비 단계에서는 다시 조준할 수 있다.

③ 이동 흔적 추적 공격

눈을 발광시키며 플레이어의 과거 이동 위치를 읽는 패턴이다.

관찰 시작 → 일정 간격으로 위치 기록 → 기록한 위치에 경고 표시 → 기록 순서대로 지면 발톱 발생

이 패턴은 BossPattern을 상속하는 체력 특수 패턴으로 구현한다.

발동 수치는 반드시 2페이즈 자체 체력을 기준으로 조절할 수 있어야 한다. 1·2페이즈 합산 체력 기준이 아니다.

발동 체력 비율, 기록 개수, 기록 간격, 공격 간격 등의 구체적인 값은 아직 확정하지 않았다.

- Leap 5장:

사용자가 “모든 프레임의 전체 윤곽을 동일하게”라고 명시적으로 선택했다.

따라서 이 9장은 같은 자세를 사용하고 눈·몸통 발광만 달라진다. 기존 제작 검증에서는 모든 알파 픽셀이 같고, 지정한 발광 영역 바깥의 RGB도 같았다.

주의:
- 전체 이미지 색상까지 동일하다는 뜻은 아니다.
- Leap 파일 이름이 달라도 실제 도약 자세가 각각 그려진 것은 아니다.
- 이 9장에 대한 윤곽 일치 검증을 Combo/Trace 에셋에도 적용됐다고 주장하면 안 된다.
- 몸 전체 윤곽을 고정하면서 서로 다른 웅크림·할퀴기 자세까지 표현할 수 있다고 설명하면 안 된다.

Combo/Trace는 동작별 주요 이미지이며, 부드러운 중간 동작까지 완성된 프레임 세트는 아니다. 본체 크기·발 위치·지면 효과 기준점의 최종 정렬도 다시 확인해야 한다.

기존에 안내한 기본 임포트 기준은 PPU 100, Pivot 중앙, Point 필터, Full Rect, 압축 없음, 투명도 사용이다. 실제 최신 설정은 파일에서 확인해줘.

6. 애니메이션 구성에 관한 마지막 논의

이전에 코덱스가 준비·공격·회수의 단일 이미지마다 클립을 만들어 본체 17개와 효과 6개, 총 23개로 나누는 구성을 제안했다.

사용자가 “왜 이렇게 클립을 다 따로 만들어?”라고 지적했고, 그 제안은 과도한 분리였다고 인정하며 철회했다.

마지막으로 제안한 간소화 방향은 다음과 같다. 아직 구현 완료된 구조는 아니다.

- 반복 재생이 필요한 Idle은 애니메이션 클립을 사용한다.
- 한 장짜리 준비·공격·회수 표현은 패턴 또는 시각 표현 담당 코드에서 SpriteResolver의 Category/Label을 전환하는 방식을 검토한다.
- 논리적인 공격 단계마다 반드시 별도의 Animation Clip이나 Animator State가 필요한 것은 아니다.
- 방향 고정은 공격 로직의 책임이며, 별도 이미지나 클립이 필수인 단계가 아니다.
- 경고 이미지는 표시·숨김과 필요한 시각 변화로 처리한다.
- 충격파는 이미지의 크기와 투명도 변화로 표현하는 방향이다.
- 지면 발톱의 상승 → 최고점 → 소멸은 하나의 비반복 애니메이션으로 구성할 수 있다.
- 추후 실제 연속 동작 프레임이 마련되면 동작 단위의 클립을 사용한다.

다만 반드시 해결할 문제가 있다.

Animator가 Idle 또는 페이즈 전환에서 SpriteResolver 값을 제어하는 동안 코드도 같은 값을 변경하면 서로 덮어쓸 수 있다.

따라서 먼저 시각 표현 제어권을 설계해야 한다. 공격 시작·종료·취소 시점에 누가 스프라이트를 제어하고, 어떻게 Idle로 복귀하는지 정해야 한다.

매 프레임 Label을 덮어쓰거나 Animator를 무작정 꺼서 해결하는 임시방편은 피한다. 구체적인 해결 구조는 최신 코드를 읽고 설명한 뒤 정한다.

철회된 23개 클립 생성 절차를 다시 진행시키지 마.

- 기존 체력 특수 패턴 검사도 같은 로봇 페이즈 조건으로 제한돼 있다.
- 따라서 3번 패턴을 기존 목록에 넣기만 해서는 2페이즈에서 동작하지 않는다.
- 2페이즈 체력 기준 발동 조건과 발동 여부 초기화·관리 방식을 설계해야 한다.
- HealthBossPatternEntry는 체력 비율과 BossPattern 참조를 가지며, 현재 페이즈 구분 필드는 없다.
- BossPattern은 ScriptableObject 기반이며 Execute(BossPatternContext) 코루틴을 실행하는 구조다.
- 기존 BossPatternRunner의 일반·특수 패턴 처리와 취소·정리 흐름을 활용해야 한다.
- 기존 Animation Event Relay에는 미사일·잡기 이벤트만 있고 2페이즈 이벤트는 없다.

현재 전환 코드는 Alien_PhaseTransition 상태의 재생 완료를 직접 확인한다. 관련 코드를 확인하지 않고 자동 전환을 추가하면 완료 감지와 충돌할 수 있다.

보스 프리팹의 BodyVisual에는 SpriteRenderer, SpriteLibrary, SpriteResolver, Animator가 있다.

프리팹에 저장된 표시 스프라이트는 새 에일리언 Idle 이미지로 변경돼 있지만, Animator 기본 상태는 기존 로봇 Idle이다. 게임 시작 시 1페이즈 외형이 정상인지도 확인해야 한다.

아직 새 도약·콤보·흔적 추적 패턴 코드나 전용 공격 프리팹이 완성돼 있다고 가정하면 안 된다.

9. 다음 작업 순서

첫째, 새 PC의 최신 파일을 읽고 위 현황과 달라진 부분을 확인해줘.

둘째, 사용자가 완료했다고 한 Idle의 실제 키프레임 저장 여부와 Animator 연결 상태를 확인해줘.

셋째, 세 패턴의 표현 구성을 최소한으로 정리하고 Animator와 코드의 SpriteResolver 제어 충돌을 해결할 구조를 설명해줘.

넷째, 필요한 Combo/Trace 카테고리와 Label, 지면 발톱 효과 애니메이션 설정을 내가 직접 할 수 있도록 단계별로 안내해줘.

다섯째, 표현 준비가 끝나면 예측 도약과 방향 고정 콤보를 기존 일반 패턴 구조에 연결하고, 이동 흔적 공격은 2페이즈 체력 기준 BossPattern 특수 패턴으로 설계해줘.

모든 단계에서 프로젝트는 직접 수정하지 말고, 내가 이해하고 직접 적용할 수 있게 안내해줘.

Idle 클립 최신 확인 결과

Alien_Phase2_Idle.anim은 키프레임 작성 및 저장이 완료돼 있다.
