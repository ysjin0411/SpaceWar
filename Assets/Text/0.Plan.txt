Unity 프로젝트의 투사체·일반 적 오브젝트 풀링 작업을 이어서 도와줘.

[작업 규칙]
- 나는 게임 클라이언트 개발자 취업 준비생이야.
- 프로젝트 파일은 절대 직접 수정하지 말고, 최신 파일을 읽은 뒤 내가 수정할 코드와 위치만 알려줘.
- 코드는 기능을 설명하는 주석을 달아줘. 필드 설명도 Tooltip 대신 주석을 사용해.
- nullable 문법은 사용하지 마.
- 한 번에 전체 작업을 설명하지 말고, 관련된 메서드 2~3개나 작은 작업 묶음 단위로 안내해.
- 내가 “했어”라고 하면 실제 저장된 최신 파일을 읽어 확인하고 다음 단계로 넘어가.
- 실행 테스트는 내가 생략하겠다고 했으므로 요구하거나 직접 실행하지 마.
- 이전 작업 경로는 C:\YSJStudy\SubPF였지만, 환경을 바꿨으니 현재 프로젝트 위치부터 확인해.
- Unity 버전은 이전 확인 기준 6000.0.68f1이야.

[목표와 구조]
UnityEngine.Pool.ObjectPool<GameObject>를 사용해서 프리팹별로 N개를 미리 생성하고 활성화·비활성화하며 재사용한다.

현재 공통 파일:
- Assets/2. Scripts/Pool/PoolObject.cs
- Assets/2. Scripts/Pool/ProjectilePoolManager.cs

PoolObject:
- Bind()로 소속 풀 연결
- MarkBorrowed()로 대여 상태 기록
- ReturnToPool()로 반납
- _isBorrowed가 false면 반납 호출을 무시함

ProjectilePoolManager:
- 인스펙터 Settings에 Prefab, PrewarmCount, MaxSize 등록
- 프리팹별 풀을 Dictionary로 관리
- N개를 모두 Get한 뒤 반납하여 미리 생성
- Spawn()은 부모 분리 → 위치·회전·크기 설정 → 활성화 순서
- 발사 정보나 적 패턴 정보는 Spawn() 반환 직후 호출자가 초기화
- 풀 반납 시 비활성화하고 매니저 자식으로 이동
- 부족하면 추가 생성함
- MaxSize는 동시 사용량 제한이 아니라 반납된 객체의 최대 보관 개수
- 씬별 매니저이며 DontDestroyOnLoad를 사용하지 않음
- 이름은 ProjectilePoolManager지만 일반 적에도 같은 구조를 사용하기로 했음

- Boss_Cruiser.cs에 List<SmallEnemy> _summonedEnemies가 있음
