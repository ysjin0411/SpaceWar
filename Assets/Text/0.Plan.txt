**다음 작업: 순서 기억형 미사일 포격 특수패턴**

이제부터는 아래 설계를 기준으로 구현해. 이전에 이야기했던 단순 순차 포격 구상보다 이 요구사항이 우선이야.

발동은 **1페이즈에서 Inspector에 설정한 체력 비율 이하가 되었을 때**야. “2페이즈 특정 체력”이라고 말한 부분은 정정하며, 이 패턴은 **1페이즈 전용**이야.

플레이어가 여러 회차의 안전지대를 미리 보고 순서를 기억한 뒤, 실제 폭격 때 그 순서대로 이동해서 살아남는 패턴을 만들 거야.

전체 흐름은 다음과 같아.

체력 조건 충족 및 패턴 예약
→ 패턴 시작 시 시스템 다이어로그 경고
→ 다이어로그 종료
→ 1회차 위험지대 표시 후 설정 시간 대기
→ 기존 표시를 유지하면서 2회차 위험지대 추가
→ 같은 방식으로 N회차까지 순서대로 모두 표시
→ 모든 회차의 예고 완료
→ 1회차 실제 미사일 폭격·폭발 연출·페이드아웃
→ 1회차 위험지대 표시 제거
→ 2회차 실제 폭격·연출·해당 표시 제거
→ N회차까지 FIFO 순서로 반복
→ 패턴 종료.

즉, **한 회차를 예고하고 즉시 폭격한 다음 다음 회차를 예고하는 방식이 아니야. 먼저 전체 회차를 예고한 뒤 실제 폭격을 시작해야 해.**

회차별 위험지대의 수명:

- 표시된 위험지대는 다음 회차를 예고하는 동안에도 계속 남아 있어.
- 전체 예고가 끝나면 모든 회차의 위험지대가 동시에 남아 있는 상태야.
- 1회차의 폭격과 연출이 끝나면 1회차 표시만 제거해.
- 아직 공격하지 않은 회차의 표시는 그대로 남겨.
- 같은 위치에 다른 회차의 경고가 겹쳐 있어도, 완료한 회차의 표시만 제거해야 해.
- 취소·사망·비활성화 때는 남은 표시와 연출을 모두 정리해야 해.

위험지대 표현:

- 각 미사일이 떨어질 위치와 폭발 반경을 연한 빨간색 원형 장판으로 표시해.
- 여러 회차의 위험지대가 겹치는 곳은 반투명 표시가 누적되어 더 진하게 보여야 해.
- 한 번만 공격하는 곳은 상대적으로 연하게 보여야 해.
- 안전지대는 해당 회차의 미사일 폭발 범위 사이에 남겨 둔 피할 수 있는 공간이야.
- 기존 공명 패턴처럼 무조건 세로 통로 하나를 생성하는 방식으로 대체하지 마.
- 다음 회차의 안전지대까지 실제 플레이어 이동 속도와 공격 간격으로 이동할 수 있어야 해.
- 예고 후 공격 위치를 다시 플레이어 위치로 변경하면 안 돼. 기억한 위치와 실제 폭격 위치가 일치해야 해.

Config 구성 의도:

- 최상위 패턴 에셋은 기존 `BossPattern`을 상속받아 체력 특수패턴 목록에 등록할 수 있어야 해.
- 최상위 패턴에는 회차별 Config를 순서대로 등록해.
- 전체 회차 수 N과 한 회차의 미사일 개수는 서로 다른 개념이야.
- 각 회차 Config에는 해당 회차에 떨어질 미사일들의 설정을 등록해.
- 각 미사일의 낙하 위치와 폭발 radius를 개별 설정할 수 있어야 해.
- 각 미사일의 폭발 이펙트 크기도 개별 설정할 수 있어야 해. 피해 반경과 시각 효과 크기의 관계를 명확하게 설명해.
- 회차 예고 시간, 실제 폭격 시작 전 First Delay, 회차 사이 이동 여유 시간 등을 서로 혼동하지 않도록 정의해.
- 전체 예고가 끝나기 전에 개별 경고의 타이머 때문에 미사일이 먼저 떨어지면 안 돼.
- 데미지와 연출 관련 값도 코드에 고정하지 말고 기존 프로젝트 방식에 맞춰 Config로 관리해.

실제 공격 연출:

- 해당 회차 차례가 되면 예고한 위치로 미사일이 화면에 떨어져 폭발해.
- 각 미사일은 설정한 반경으로 피해를 판정해.
- 폭발 연출 후 DOTween으로 자연스럽게 사라지게 해.
- 해당 회차의 모든 미사일 연출이 끝나면 그 회차의 경고를 제거하고 다음 회차로 진행해.
- 패턴 실행 중 사용하는 큐·타이머·생성 객체 목록은 공유 ScriptableObject의 지속 상태로 잘못 저장하지 않도록 해.

아직 구체적으로 확정하지 않은 세부사항은 임의로 확정된 것처럼 말하지 마. 특히 First Delay의 기준 시점, 낙하 위치 좌표 기준, 같은 회차에서 여러 폭발이 겹칠 때 피해 처리 방식은 기존 코드와 요구사항에 맞춰 설명하고 정하자.

**재사용 검토 대상과 주의점**

일반 미사일 관련 `BossAlienMissilePattern`, `BossAlienMissileConfig`, `BossAlienMissile`, `BossAlienMissileExplosion`, `BossAlienExplosionDamage`가 이미 있어. 기존 클래스의 이동 방식과 종료 처리를 확인한 뒤 재사용 가능한 부분을 판단해. 새 포격을 위해 일반 미사일 동작을 망가뜨리지 마.

시스템 다이어로그는 `BossEnemy.RequestSystemDialogue`, `SystemDialogueCompleted`와 기존 `SystemDialogueUI`를 사용해. 완료 이벤트는 요청 전에 구독하고 취소 시 해제해. 기존 UI의 중복 메시지 처리도 확인해.

`BossAlienPhaseOneConfig`에 과거 구상의 `BarrageFirstDelay`, `BarrageCooldown`이 남아 있을 수 있어. 이것만 보고 미사일 특수패턴이 이미 구현됐다고 판단하지 마. 이번 패턴의 발동 조건은 시간 주기나 쿨다운이 아니라 체력 임계값이야.

먼저 관련 최신 파일을 확인한 뒤, 구현된 부분과 새로 필요한 부분을 짧게 구분해 줘. 그다음 이번 미사일 포격의 Config 구조부터 작은 단계 하나로 안내해. 전체 코드를 한 번에 쏟아내지 마.
