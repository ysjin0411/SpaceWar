4-5. 상태가 바뀌면 여러 담당자가 반응한다
[StageFlowManager.ChangePhase() (line 209)](C:/YSJ/SubPF/Assets/2. Scripts/Stage/StageFlowManager.cs:209)는:

세부 생성 묶음과 패턴은 8단계에서 다루고, 지금은 스테이지 상태가 생성 허용 여부에 연결된다는 점을 기억하면 돼.
4-9. 중간보스 이후의 맵 이동은 씬 전환이 아니다

[StageTransitionManager의 구간 이동 (line 229)](C:/YSJ/SubPF/Assets/2. Scripts/Stage/StageTransitionManager.cs:229)에서는 LoadScene()을 사용하지 않아.
같은 전투 씬 안에서:
1. 플레이어 조작을 막는다.
2. 잠시 대기한다.
3. 플레이어를 퇴장 위치로 이동시킨다.
4. 배경 스크롤을 멈춘다.
5. 이전 구간의 적과 지정된 적 공격 객체들을 정리한다.

그래서 플레이어 객체는 유지되고, 그 객체에 연결된 이번 전투 상태도 이어지는 구조야.
무대 비유로는:
배우가 잠깐 퇴장한 사이에 배경과 이전 장면의 소품을 치우고, 같은 배우가 다시 입장한다.

마을에서는 창을 바꾸고, 전투에서는 배경을 바꾸는 차이는 있지만, 둘 다 화면이 달라진다고 반드시 씬을 바꿔야 하는 것은 아니다라는 사례야.
BackgroundScroller는 배경 두 장을 옆으로 이어 놓고 왼쪽으로 이동시켜. 뒤로 넘어간 배경을 다시 오른쪽 끝에 배치해서 계속 이동하는 것처럼 보여 줘.
4-10. 진행 바 100%는 보스 처치 완료가 아니다

상태	진행도

따라서 이 바는 일반 전투 구간의 진행과 보스 도달 위치를 표현하는 표시에 가까워.
최종보스가 살아 있어도 이미 100%야. 클리어 여부는 StagePhase.Cleared로 판단해야 해.
현재 Failed는 별도 분기가 없어서 기본값 0%를 반환한다는 점도 알아두면 좋아. 실패 시 진행도를 유지할지 여부는 추후 표시 정책으로 정리할 부분이야.
4-11. 클리어와 사망은 어떻게 결과창으로 연결될까?
클리어 경로는 다음과 같아.

→ BossEncounterManager가 처치 보고
→ FlowManager가 Cleared로 변경
→ StageResultUI가 결과 표시

사망 경로는 다음과 같아.
PlayerController의 Died 이벤트
→ StageManager가 감지
→ FlowManager의 FailStage()
→ Failed로 변경
→ StageResultUI가 결과 표시

[StageResultUI.ShowResult() (line 229)](C:/YSJ/SubPF/Assets/2. Scripts/UI/StageResultUI.cs:229)는 먼저 시간을 멈추고 결과를 구성해.
처리	클리어	실패
경험치·골드 획득량 표시	표시	표시
클리어 시간 표시	표시	숨김
최고 클리어 기록 갱신 시도	실행	실행하지 않음
업적 전체 평가	실행	이 경로에서는 실행하지 않음
재시작 버튼	숨김	표시


여기서 결과창은 획득한 경험치·골드를 보여 주는 역할이야. ShowResult()에서 표시된 양을 다시 지급하는 코드는 없어.
2단계에서 봤듯 경험치는 획득 처리 중 저장되므로, 결과창이 열리는 순간 처음 확정되는 구조가 아니야.
현재 복귀 버튼은 StageSelect 씬으로 돌아가고, 재시작은 선택 정보를 유지하면서 전투 씬을 다시 로드해.
마을 개편 시에는 결과창과 PauseManager 양쪽의 복귀 경로를 함께 바꿔야 해. 출격 NPC 쪽만 바꾸면 전투 종료 후에는 기존 스테이지 선택 씬으로 돌아가게 돼.
4-12. 이번 범위의 객체지향과 개편 관점
현재 스테이지는 역할 분리가 대체로 의미 있어. 준비, 상태 진행, 이동 연출, 보스 배치가 서로 다른 이유로 바뀌기 때문이야.
특히 StagePhase를 enum과 분기로 처리하는 현재 규모에서, 모든 단계를 별도 상태 클래스로 만드는 작업부터 할 필요는 없어.
다만 다음 경계는 짚고 넘어갈 만해.
지점	현재 특징	검토할 방향
StageFlowManager	진행 상태와 시작 문구·타이머 UI를 함께 처리	연출이 커지면 표시 책임 분리
BossWarningUI	연출 완료가 다음 전투 단계의 시작 조건	단순 장식 UI가 아니라 필수 진행 요소임을 명확히 하기
StageResultUI	결과 표시와 최고 기록 저장·업적 평가를 함께 처리	결과 확정과 표시를 분리할 여지
ChangePhase()	중복·종료 후 변경은 막지만 모든 전환 순서를 검증하지는 않음	진행 변경의 진입점 관리
여러 화면의 씬 이동	각 화면에 목적지가 직접 들어 있음	마을 개편 시 출격·취소·복귀 흐름을 일관되게 관리

특히 결과창이 최고 기록 저장까지 담당한다는 것은, 나중에 결과 UI를 교체할 때 게임 기록 처리도 함께 건드릴 수 있다는 뜻이야. 이것은 과도한 클래스 분리보다 책임이 섞인 쪽의 검토 사항이야.
이번 단계에서 네가 설명할 수 있어야 할 흐름은 이거야.
StageManager가 선택 정보와 저장 기록으로 플레이어를 생성하고 전투 시스템을 연결한다. StageFlowManager는 진행 상태를 관리하며, 각 담당자가 상태 변경에 반응한다. 연출 완료와 보스 처치가 다시 FlowManager에 보고되어 다음 단계로 넘어간다. 중간 구간 이동은 같은 씬에서 처리하고, 최종 클리어 또는 사망은 결과창으로 연결된다.

마을 개편은 이 흐름의 앞쪽 선택 UI와 뒤쪽 복귀 경로를 중심으로 바꾸면 연결할 수 있어. 다음 5단계에서는 그 안에서 움직이는 PlayerController의 이동·조작 제한·피격·사망을 살펴보면 돼.
