최초 방향은 다음 계산으로 구해.
최초 방향 = 조준 기준점 - 실제 FirePoint 위치
FirePoint가 (9, 4)에 있다고 가정하면:
(9, -4) - (9, 4)
= (0, -8)
아래를 향하는 방향이고, 각도로는 -90도야.
이 방향에서 -82.5도를 더 회전하므로:
시작: -90도
종료: -172.5도
아래에서 시작해 왼쪽에 가까운 방향까지 쓸게 돼.
중간 각도는 다음 식으로 계산해.
현재 각도 = 시작 각도 + 전체 쓸기 각도 × 진행률
진행률 = 경과 시간 ÷ 쓸기 시간
경과 시간	진행률	위 예시의 레이저 각도
0초	0%	-90도
0.6초	50%	-131.25도
1.2초	100%	-172.5도


현재 설정의 각속도는 -82.5 ÷ 1.2, 즉 초당 -68.75도야.
플레이어를 계속 추적하는 레이저는 아니야. 설정된 조준점으로 시작 방향을 정하고, 정해진 각도만큼 회전해.

이 구조에서는 블랙홀을 발사했다고 바로 패턴이 끝나지 않아. 블랙홀의 소멸까지 기다리므로, 그동안 Runner는 다음 보스 패턴을 시작하지 않아.
11-10. 블랙홀은 생성 직전에 플레이어 위치를 한 번 확인한다
현재 [블랙홀 패턴 에셋](C:/YSJ/SubPF/Assets/6.Configs/Enemy/Patterns/Boss/BossHeadBlackHolePattern.asset)은 플레이어 상대 위치를 사용해.
목적지 = 생성 직전의 플레이어 위치 + (0.8, 0)
즉, 플레이어보다 오른쪽으로 0.8 떨어진 곳을 목적지로 잡아.
그 뒤 플레이어가 이동해도 목적지를 계속 갱신하지 않아.
현재 실행 수치는:
구간	현재 설정
보스 원위치 이동	0.6초
블랙홀 비행	1초
비행 중 크기	완전히 펼친 크기의 1%
확대	0.5초
활성 상태	5초
소멸	0.5초
회전 속도	초당 270도


비행 중 크기는 스프라이트의 가로·세로 배율이 1%라는 의미야.
이동 중이거나 확대 중일 때는 아직 흡입과 피해를 적용하지 않아. Active 상태에 들어가야 실제 공격 기능이 작동해.
11-11. 블랙홀에는 흡입 범위와 피해 범위가 따로 있다
범위는 스프라이트의 크기를 기준으로 계산해.
흡입 반경
= 스프라이트 로컬 너비 × 0.47을 월드 크기로 변환

피해 반경
= 흡입 반경 × 0.3
현재 프리팹의 비율이 0.47과 0.3이야.
넓은 바깥 원
→ 플레이어를 끌어당김

작은 안쪽 원
→ 주기적으로 피해
비유하면:
소용돌이 바깥에서는 물살에 끌리고,
중심 가까이 들어가면 실제 피해를 받는 구조야.

범위 판정 방식에도 차이가 있어.
판정	사용하는 위치
흡입 범위 진입	플레이어 Transform의 중심
피해 범위 접촉	플레이어 콜라이더에서 블랙홀 중심에 가장 가까운 점


따라서 피해는 플레이어 중심이 안쪽 원에 들어와야만 발생하는 것이 아니야. 몸체의 가장자리가 피해 원에 닿아도 판정될 수 있어.
11-12. 흡입은 플레이어 입력에 ‘외부 속도’를 더하는 방식이다
블랙홀이 플레이어 위치를 직접 덮어쓰지는 않아.
[블랙홀의 FixedUpdate (line 270)](C:/YSJ/SubPF/Assets/2. Scripts/Enemy/Boss/Patterns/Boss_Head/BossBlackHole.cs:270)는 중심 방향의 속도를 플레이어에 등록해.
흡입 방향 = 블랙홀 중심 - 플레이어 위치
외부 속도 = 정규화한 흡입 방향 × 흡입 속도
현재 흡입 속도는 2.5야.
[PlayerController.FixedUpdate (line 114)](C:/YSJ/SubPF/Assets/2. Scripts/Player/PlayerController.cs:114)에서는:
최종 이동 속도
= 플레이어 입력 속도
+ 활성화된 외부 효과들의 속도
로 합산해.
가령 블랙홀이 오른쪽에 있고, 플레이어가 왼쪽으로 속도 5만큼 움직인다고 가정하면:
플레이어 입력: 왼쪽 5
블랙홀 흡입: 오른쪽 2.5
합산 결과: 왼쪽 2.5
반대로 블랙홀 방향으로 움직이면 두 속도가 더해져.
즉, 흡입 중에도 조작 자체는 유지되고, 이동 결과에 끌어당김이 반영되는 구조야.
외부 속도는 블랙홀 자신을 식별자로 저장하므로, 매 프레임 2.5가 계속 누적되지 않아. 같은 블랙홀의 값을 갱신하는 방식이야.
또 중심을 지나쳐 버리지 않도록, 아주 가까운 거리에서는 흡입 속도를 낮춰.
11-13. 블랙홀의 피해와 종료는 이렇게 처리한다
현재 설정은:
피해량: 10
피해 간격: 0.5초
활성 상태에서 피해 원에 닿아 있고 다음 피해 시각이 지났다면 Player.TakeHit(10)을 호출해.
이 코드는 방패에 TryBlockDamage를 요청하는 경로 없이 플레이어에게 직접 피해를 요청해.
소멸을 시작하면:
상태를 Fading으로 변경
→ 플레이어에 등록한 흡입 속도 제거
→ 외형 축소와 투명화
→ 오브젝트 제거
해.
보스가 죽거나 비활성화되어도 소멸을 시작하고, 블랙홀 자체가 비활성화될 때도 외부 속도를 해제해.
따라서 흡입은 블랙홀의 상태와 연결되어 있고, 그림이 사라지는 연출에 들어갈 때 이미 해제돼.
참고로 [DefaultExecutionOrder(-100)]도 붙어 있어. 블랙홀이 먼저 외부 속도를 갱신하고, 이후 플레이어가 그 값을 합산하도록 순서를 앞당긴 설정이야.
11-14. 혼란 패턴은 방향 반전이 아니라 키 입력 시험이다
이름만 보면 조작 방향을 뒤집는 효과를 떠올릴 수 있지만, 현재 구현은 정해진 문자들을 순서대로 입력하는 미니게임이야.
[BossHeadConfusionPattern.cs (line 53)](C:/YSJ/SubPF/Assets/2. Scripts/Enemy/Boss/Patterns/Boss_Head/BossHeadConfusionPattern.cs:53)가 전체 진행을 맡고, [MentalConfusionUI.cs](C:/YSJ/SubPF/Assets/2. Scripts/UI/MentalConfusionUI.cs)가 입력과 결과를 처리해.
현재 [혼란 패턴 에셋](C:/YSJ/SubPF/Assets/6.Configs/Enemy/Patterns/Boss/BossHeadConfusionPattern.asset)은:
설정	현재 값
입력할 문자 수	12개
사용할 문자 후보	QWERTASDFGZXCVB
전체 제한 시간	8초
허용 생명 수	3
최종 실패 피해	50
실패 시 카메라 흔들림	0.3초


문자는 후보 목록에서 각 자리마다 무작위로 뽑아.
따라서 다음처럼 같은 문자가 반복될 수 있어.
Q → A → A → R → Z → ...
후보 목록에 중복 문자를 넣지 못하도록 검사하지만, 생성되는 문제에서 같은 문자가 다시 나오는 것은 허용해.
11-15. 게임을 멈췄는데 어떻게 8초가 흐를까?
혼란 패턴은 기존 정지나 조작 제한 상태가 끝나기를 기다린 뒤 경고를 표시하고, 시험 직전에 다음을 실행해.
기존 Time.timeScale 저장
→ Time.timeScale = 0
→ 입력 UI 생성
전투의 일반적인 시간 진행은 멈추지만, UI는 다른 시간값을 사용해.
전투 시간: Time.deltaTime
시험 시간: Time.unscaledDeltaTime
unscaledDeltaTime은 이 시간 배율에 영향을 받지 않으므로, 전투가 정지한 동안에도 시험 제한 시간은 줄어들어.
UI의 이동·점멸 연출도 SetUpdate(true)로 정지 중에 진행하도록 되어 있어.
비유하면:
경기장 시계는 멈추고, 시험 감독의 별도 초시계는 계속 가는 거야.

또 Time.timeScale = 0이 모든 스크립트 호출을 없애는 것은 아니야. UI의 Update는 입력을 검사하고, 별도 시간 기준으로 진행을 관리해.
11-16. 정답·오답·실패 판정은 정확히 어떻게 할까?
[MentalConfusionUI.Update (line 279)](C:/YSJ/SubPF/Assets/2. Scripts/UI/MentalConfusionUI.cs:279)는 A~Z 중 이번 프레임에 새로 눌린 키를 검사해.
정답 조건은 두 가지야.
이번 프레임에 눌린 알파벳 키가 정확히 하나
그리고 현재 요구하는 문자와 일치
입력 상황	결과
요구한 문자 하나를 누름	정답
다른 알파벳을 누름	오답
같은 프레임에 알파벳 여러 개를 누름	오답
알파벳 입력이 없음	그대로 대기


키를 누르고 있기만 하면 연속 정답이 되는 방식은 아니야. GetKeyDown으로 새로 누른 시점을 확인해.
정답이면:
현재 문자 완료
→ 다음 문자로 진행
→ 완료 문자를 위로 띄우며 제거
→ 남은 문자들을 왼쪽으로 이동
오답이면:
생명 하나 감소
→ 실패 피드백 표시
→ 현재 문자는 유지
세 번째 오답으로 생명이 0이 되면 최종 실패야. 8초가 지나도 실패하고.
8초는 문자마다 주어지는 시간이 아니라, 12개 전체를 입력할 시간이야.
문제를 전부 맞히거나 실패가 결정되면, 마지막 피드백 연출이 보일 시간을 조금 기다린 뒤 결과를 확정해.
11-17. 틀릴 때마다 50 피해를 받는 것은 아니다
오답과 최종 실패를 구분해야 해.
첫 오답 → 생명 감소
두 번째 오답 → 생명 감소
세 번째 오답 → 시험 실패
→ 패턴이 실패 결과 확인
→ 피해 50 요청
시간 초과도 같은 최종 실패 경로를 타.
실패 시 전체 흐름은:
시험 UI 제거
→ 플레이어에게 피해 50
→ 카메라 흔들림
→ 실패 시스템 메시지
→ 연출 완료 대기
→ 이전 시간 배율 복원
실패 연출이 끝날 때까지 전투는 정지된 상태를 유지해. 카메라 흔들림과 시스템 메시지는 정지 중에도 진행하도록 설정돼 있어.
성공하면 실패 피해와 실패 연출 없이 정리하고 전투로 돌아가.
현재 PlayerController.TakeHit은 시간 배율이 0이라는 이유로 피해를 막지는 않아. 조작 가능 여부와 사망 여부 등을 확인하므로, 전투 시간을 멈춘 상태에서도 이 실패 피해 호출은 처리될 수 있어.
11-18. 혼란 패턴의 finally는 ‘시험장 철수’를 담당한다
혼란 패턴은 입력 UI 외에도 여러 상태를 바꿔.
- 시스템 메시지 이벤트 구독.
- 전투 시간 정지.
- UI 생성.
- 실패 시 카메라 이동.
그래서 [종료 정리 구간 (line 192)](C:/YSJ/SubPF/Assets/2. Scripts/Enemy/Boss/Patterns/Boss_Head/BossHeadConfusionPattern.cs:192)에서:
이벤트 구독 해제
→ 카메라 흔들림 종료
→ 카메라 위치 복원
→ 남은 시험 UI 제거
→ 시간 배율 복원
을 처리해.
여기서 ownsPause는 이번 패턴이 직접 시간 정지를 시작했는지를 기록하는 값이야. 자신이 정지시키기 전에 취소되었다면 시간을 임의로 복원하지 않도록 구분해.
실패 피해로 플레이어가 죽었다면 이전 시간 배율로 되돌리지 않고 0을 유지해.
또 UI가 진행 중에 비활성화되면 Cancelled 결과를 기록해서, 정상적인 성공·실패와 취소를 구분해.
비유하면:
시험이 끝나든 중간에 취소되든, 감독이 문제지를 치우고 카메라와 경기장 시계를 정리한 뒤 나가는 구조야.

11-19. 세 패턴의 ‘종료 시점’을 비교해 보자
이 차이를 알면 보스가 언제 다음 행동으로 넘어가는지도 이해할 수 있어.
패턴	Runner가 기다리는 범위
레이저	경고 → 쓸기 → 레이저 소멸 → 보스 복귀
블랙홀	경고 → 생성 → 블랙홀 활성 → 소멸
혼란	경고 → 입력 시험 → 필요하면 실패 연출 → 정리


레이저를 생성하거나 블랙홀을 발사하는 순간 Execute가 끝나는 것은 아니야.
해당 공격의 주요 진행과 종료 연출을 기다린 뒤 Runner에 제어가 돌아가.
이번 Head 구조에서 역할 분리가 실제로 쓰이는 지점도 여기에 있어.
- 패턴은 “언제 생성하고 언제까지 기다릴지”를 관리해.
- 공격 오브젝트는 자신의 외형·범위·피해를 관리해.
- 플레이어는 전달받은 이동 효과와 피해를 적용해.
- 입력 UI는 시험을 진행하고 결과를 제공해.
다음은 기존 구성의 12단계, 전체 구조를 연결해서 되짚는 단계야. 말한 대로 실제 수정은 기능 추가 이후로 두고, 지금까지 읽은 시스템들이 어떻게 하나의 게임 흐름으로 이어지는지 정리하면 돼.
