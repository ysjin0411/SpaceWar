Animation Clip의 역할
Animation Clip은 “시간에 따라 어떤 값을 바꿀지” 기록한다.
일반적으로 Sprite 애니메이션을 만들면 다음 두 방식이 있다.
직접 Sprite를 기록하는 방식
SpriteRenderer.Sprite
→ Enemy1_Idle_0
→ Enemy1_Idle_1
→ Enemy1_Idle_2
이 방식은 클립에 Enemy1의 실제 Sprite가 들어간다. 따라서 Enemy2가 같은 클립을 사용하면 Enemy1의 모습이 나온다.
Sprite Resolver를 기록하는 방식
SpriteResolver Label
→ Frame0
→ Frame1
→ Frame2
이 방식은 실제 Sprite가 아니라 Library의 주소를 변경한다. 따라서 Enemy마다 다른 Sprite Library를 연결하면 같은 클립을 재사용할 수 있다.
네 프로젝트의 [Normal/Idle.anim](C:/YSJStudy/SubPF/Assets/3. Animations/Enemy/Normal/Idle.anim)은 SpriteRenderer.Sprite가 아니라 SpriteResolver.m_SpriteHash를 변경하고 있다. 즉, 재사용에 적합한 Resolver 방식으로 이미 만들고 있어.
Animator Controller의 역할
Animator Controller는 애니메이션 파일이 아니라 애니메이션들의 진행 흐름이다.
Idle
  ├─ 공격 조건 발생 → Attack
  ├─ 피격 조건 발생 → Hit
  └─ 체력 0 → Die
예를 들어 Controller에 이런 파라미터를 만들 수 있다.
Attack : Trigger
Hit    : Trigger
IsDead : Bool
코드에서:
_animator.SetTrigger("Attack");
_animator.SetTrigger("Hit");
_animator.SetBool("IsDead", true);
라고 요청하면 Controller가 조건에 맞는 State로 이동하고 그 State에 연결된 Clip을 재생한다.
Animator Controller는 Animation Clip들과 전환을 상태 머신으로 관리하며, Animation Clip이 하나뿐이어도 GameObject에서 재생하려면 Controller에 배치해야 한다. Unity Animator Controller 문서
Animator 컴포넌트의 역할
Animator는 프리팹에 붙어 있는 실행기다.
Animator
└─ Controller: EnemyCommon.controller
Animator 자신은 Idle의 프레임을 저장하지 않는다. 연결된 Controller를 읽고 Controller가 선택한 Clip을 실행한다.
Unity 공식 문서도 Animator 컴포넌트가 Controller를 참조하고, Controller가 어떤 Clip을 언제 재생·전환할지 결정한다고 설명한다. Unity Animator 컴포넌트 문서
네 프로젝트의 현재 상태
현재 확인되는 구조는 다음과 같다.
Normal/Idle.anim과 Boss/Idle.anim은 키프레임 시간과 Resolver 값이 동일함
Normal과 Boss가 각각 별도의 Controller를 사용함
그런데 FastEnemy와 Boss_Dog가 동일한 Normal/Idle.spriteLib를 참조하고 있음
Boss 전용 Sprite Library는 아직 없음
따라서 현재는 같은 역할의 Idle Clip을 중복 생성한 상태에 가깝다.
원하는 구조로 정리하면 다음과 같다.
공용
├─ EnemyCommon_Idle.anim
└─ EnemyCommon.controller

Enemy1 프리팹
├─ Sprite Library → Enemy1.spriteLib
├─ Sprite Resolver
└─ Animator → EnemyCommon.controller

Enemy2 프리팹
├─ Sprite Library → Enemy2.spriteLib
├─ Sprite Resolver
└─ Animator → EnemyCommon.controller
둘의 Category와 Label은 반드시 같아야 한다.
Idle / Frame0
Idle / Frame1
Idle / Frame2
Idle / Frame3
Sprite만 다르게 연결한다.
언제 Controller까지 공유하지 않는가
행동 흐름까지 같다면 Controller도 공유한다.
Enemy1: Idle → Attack → Hit → Die
Enemy2: Idle → Attack → Hit → Die
반대로 보스처럼 상태 구조가 다르면 Controller는 분리해도 된다.
일반 적 Controller
Idle → Attack → Die

보스 Controller
Enter → Idle → PatternA → PatternB → Groggy → Die
이 경우에도 Idle.anim 자체는 같은 Label 구조를 사용한다면 공유할 수 있다.
정리하면:
동작 타이밍까지 같음
→ Clip 공유

상태와 전환 구조까지 같음
→ Controller도 공유

외형만 다름
→ Sprite Library만 교체

상태 구조는 같지만 Clip 타이밍이 다름
→ Animator Override Controller 고려
네 경우에는 우선 공용 Idle Clip + Enemy별 Sprite Library 구조를 잡는 것이 정확하다.
