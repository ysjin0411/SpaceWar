# Space War

무기 교체와 보스 패턴 공략을 중심으로, 퀘스트·보상·장비 성장을 연결한 Unity 기반 2D 액션 게임입니다.

마을에서 장비와 퀘스트를 준비하고, 스테이지에서 적과 보스를 처치해 보상을 획득합니다. 획득한 보상으로 새로운 무기를 구매하고 다음 스테이지에 도전하는 흐름으로 구성했습니다.

노션으로 돌아가기 https://stormy-tsunami-815.notion.site/41e50e6167c180568c0dd9d30b724801?source=copy_link

| AI 활용 | Codex를 활용한 구현·수정·검토 및 AI 기반 리소스 제작 |

## 핵심 플레이 흐름

마을에서 준비 → 스테이지 전투 → 보스 공략 → 보상 획득 → 장비 성장 → 다음 스테이지 도전

- 캐릭터와 장착 무기를 선택해 전투를 준비합니다.
- 일반 전투와 중간 보스, 최종 보스 구간을 진행합니다.
- 상황에 맞게 장착한 무기를 교체하고 증강을 선택합니다.
- 퀘스트와 스테이지 보상을 통해 성장합니다.
- 보스 처치 후 등장하는 트레져박스를 타격해 보상을 획득합니다.

## 주요 구현 기능

### 1. 캐릭터와 무기

- 원거리·근거리 캐릭터에 맞는 무기와 공격 방식을 구현했습니다.
- 최대 3개의 무기를 장착하고 전투 중 교체할 수 있습니다.
- 무기마다 공격력, 공격 주기, 충전량 등 서로 다른 상태를 관리합니다.
- 전투 중 증강 선택을 통해 무기 성능을 강화합니다.

**설계 포인트**

`WeaponData`에는 무기의 기본 설정을,
`WeaponRuntimeState`에는 현재 공격력·쿨타임·충전량 등 전투 중 변하는 값을 저장합니다.

원본 설정과 플레이 중 상태를 분리해, 증강 효과가 원본 데이터에 영향을 주지 않도록 구성했습니다.

### 2. 스테이지 진행과 적 생성

- 일반 전투 → 중간 보스 → 구간 전환 → 일반 전투 → 최종 보스로 진행됩니다.
- 클리어와 실패를 포함한 진행 단계를 `StagePhase`로 구분합니다.
- 적 생성 패턴은 쿨타임과 가중치를 기준으로 선택합니다.
- 보스 상태와 진행 단계에 따라 일반 적 생성을 제어합니다.

**설계 포인트**

`StageFlowManager`가 진행 단계와 시간을 관리하고,
`EnemySpawner`는 `PhaseChanged` 이벤트를 받아 생성 동작을 변경합니다.

적 생성은 패턴 선택과 실제 배치 실행을 나누어,
새로운 생성 패턴을 추가할 때 진행 관리 코드를 함께 수정하는 범위를 줄였습니다.

### 3. 보스 패턴

- 보스마다 서로 다른 공격 패턴과 전투 흐름을 구성했습니다.
- `BossEncounterManager`가 보스 등장과 교체를 관리합니다.
- `BossPatternRunner`가 우선순위별 대기열을 관리하고 다음 패턴을 실행합니다.
- 개별 공격 동작은 `BossPattern` 단위로 분리했습니다.

**설계 포인트**

보스의 등장 관리, 패턴 실행 순서, 개별 공격 동작을 분리했습니다.
이를 통해 패턴을 추가하거나 실행 순서를 조정할 때 수정 대상을 명확히 했습니다.

### 4. 트레져박스와 보상

- 보스 처치 후 트레져박스 보상 과정을 제공합니다.
- 타격에 따른 피해 누적, 추가 타격 대기, 등급 상승, 개봉을 구분합니다.
- 상자의 상태에 따라 입력 처리와 연출이 달라집니다.

**설계 포인트**

`TreasureBoxState`로 상태를 명시하고,
현재 상태에서 허용하는 타격과 전환만 처리하도록 구성했습니다.

상태 변경과 개봉 이벤트를 통해 보상 처리와 연출을 연결했습니다.

### 5. 퀘스트

- 퀘스트 수락, 진행도 확인, 완료 조건 판정, 보상 수령을 구현했습니다.
- 퀘스트 진행 상태를 저장해 재실행 후에도 이어갈 수 있습니다.
- 퀘스트의 설정 데이터와 플레이어의 진행 기록을 분리했습니다.

**설계 포인트**

`QuestService`가 퀘스트 상태 변경과 보상 처리 규칙을 담당하고,
UI는 진행 상태를 표시하고 사용자의 요청을 전달합니다.

화면 표시와 퀘스트 규칙을 분리해 UI 변경이 진행 로직에 미치는 영향을 줄였습니다.

### 6. 프로필별 JSON 저장

- 로컬 프로필별로 게임 진행 정보를 저장합니다.
- 성장 정보, 보유 무기, 캐릭터별 장착 정보, 퀘스트와 스테이지 진행 정보를 관리합니다.
- 저장 위치는 `Application.persistentDataPath`를 사용합니다.

**설계 포인트**

`GameSessionManager`는 이번 플레이의 선택 정보를 전달하고,
`SaveManager`는 재실행 후에도 유지할 정보를 관리합니다.

저장 시 임시 파일에 먼저 기록한 뒤 기존 파일을 교체하는 방식으로,
파일을 직접 덮어쓰는 과정에서 발생할 수 있는 손상 위험을 줄였습니다.

> 프로필 ID는 로컬 저장 데이터를 구분하기 위한 기능입니다.
> 서버 기반 계정 인증 기능은 포함하지 않습니다.

### 7. 투사체 풀링

- 프리팹별 `ObjectPool<GameObject>`로 투사체를 재사용합니다.
- 반복되는 생성과 파괴를 줄이도록 구성했습니다.
- 풀에서 다시 대여된 객체를 이전 참조가 잘못 처리하지 않도록 대여 버전을 관리합니다.

**설계 포인트**

같은 GameObject라도 재사용 시점에 따라 다른 투사체로 취급해야 합니다.
`PoolObject.BorrowVersion`을 통해 객체 참조와 대여 시점을 함께 구분합니다.

### 8. 장비 관리 UI

- 장비 목록, 구매, 장착 상태를 관리합니다.
- `EquipmentModel`, `EquipmentPresenter`, `EquipmentManageView`로 역할을 나눴습니다.
- 데이터 처리와 화면 표시를 분리해 UI 수정 시 영향을 줄였습니다.

## AI 활용 방식

게임의 플레이 흐름과 기능 요구사항과 구체적인 설계방향을 정하고,
AI를 구현과 검토를 돕는 도구로 활용했습니다.

- 필요한 기능과 제약 조건을 설명해 구현 초안을 작성했습니다.
- 제안된 구조를 플레이 의도와 비교하고 수정 방향을 결정했습니다.
- 실행 결과를 확인하며 입력, 전투 흐름, UI, 저장 동작을 조정했습니다.
- 캐릭터, 배경, UI 등 게임 리소스 제작에 AI를 활용했습니다.

단순한 기능 추가뿐 아니라,
전투 중 상태와 영구 저장 정보의 구분,
스테이지 진행과 적 생성의 연결,
보상 획득 이후 성장 흐름을 함께 검토했습니다.
